# 上線、維護與伺服器：你該注意什麼

寫給非工程師背景的店主，以及幫忙做站的人。台灣市場情境。

---

## 0. 先講最重要的一件事

**這個 repo 裡的網站不能收錢。**

不是還沒做完，是**前端本來就不該做這件事**。所有價格、庫存、折扣都寫在瀏覽器裡，任何人打開開發者工具就能把 `NT$580` 改成 `NT$1`，然後「結帳」。真正的商店，價格與庫存一定要在使用者碰不到的伺服器上重新計算一次。

所以第一個決定不是「主機租哪家」，而是：**這家店的訂單與金流由誰負責。**

---

## 1. 三條路，先選一條

### A. 開店平台（**給你朋友的建議：先走這條**）

SHOPLINE、Cyberbiz、91APP、Shopify、easystore。

- **費用**：月費約 NT$1,000–4,000，加上金流手續費 2–3%。
- **給你的**：商品後台、訂單管理、金流（綠界／藍新／街口）、超商取貨串接、電子發票、會員、優惠券、EDM、報表 —— 全部現成。
- **代價**：版面被平台的模板限制住，客製要用它們的樣板語言，資料在別人家。
- **為什麼推薦**：一個剛起步的選品店，你 90% 的時間該花在選品、拍照、寫文案、經營 IG，不是在處理「超商取貨 API 回傳格式又改了」。平台一個月幾千塊買掉的是這些麻煩。

那這個 repo 還有什麼用？很多：

1. **品牌與版面的原型** —— 拿去跟平台的模板對照，知道自己要什麼、要改哪裡，或直接請人照這個版做成平台主題。
2. **行銷落地頁（Landing Page）** —— 開團、新品發表、聯名活動，用這個做一頁式頁面掛在自己的網域，結帳按鈕導去平台。這種頁面平台做起來反而綁手綁腳。
3. **設計語言的定案** —— 顏色、字體、間距、商品卡長怎樣，都在 `style.css` 裡定好了，之後不管換到哪個平台都有依據。

### B. 靜態前端 + 外掛結帳（中間路線）

這個 repo 的版面留著，結帳交給第三方：

- **Shopify Storefront API** —— 商品與訂單在 Shopify，前端完全自己做（Headless）。
- **Snipcart / Ecwid** —— 貼一段 JS 就有購物車與結帳，適合品項少。
- **Stripe Payment Links / Checkout** —— 每個商品一條付款連結，最簡單但沒有購物車概念；注意 Stripe 對台灣本地超商取貨、電子發票的支援不足。

適合：品項少（<20）、想保留完整版面控制權、有人能維護。

### C. 完全自建（Next.js + 資料庫 + 綠界／藍新金流）

最自由，也最貴。你需要處理下面第 4 節列的每一項。除非之後生意做大、有專職工程師，否則不建議一開始就走這條。

**成本感覺（月）**：A 約 NT$1,500–4,000｜B 約 NT$0–2,000＋抽成｜C 主機 NT$500–3,000 ＋ **你的時間**（這才是最大的一筆）。

---

## 2. 網域與 DNS（不管走哪條路都要）

1. **買網域**：Cloudflare Registrar（最便宜、不加價續約）、Gandi、Namecheap。`.com` 一年約 NT$400–600。
   - 早點買。IG bio 一旦放出去就很難換。
2. **DNS 放 Cloudflare**（免費）：解析快、自帶 CDN 與基本防護，之後換主機只要改一筆記錄。
3. **設定**：主機商會給你一組 A record 或 CNAME，照貼就好。
4. **一定要做的兩件事**：
   - `www.你的網域` 與 `你的網域` 擇一為主，另一個 301 轉址過去（避免 SEO 分散）。
   - 全站強制 HTTPS。
5. **Email**：`hello@你的網域` 比 Gmail 有信任感。Google Workspace 約 NT$200/人/月，或 Cloudflare Email Routing 免費轉寄到既有信箱。

---

## 3. 靜態網站怎麼上線（這個 repo 的情況）

三家都免費、都自動配 HTTPS、都能接自訂網域：

| 平台 | 適合 | 部署方式 |
|---|---|---|
| **Cloudflare Pages** | DNS 已在 Cloudflare | 連 GitHub repo，選 `shop/` 當根目錄 |
| **Vercel** | 之後可能升級成 Next.js | 連 GitHub repo，Framework 選 Other |
| **Netlify** | 想用表單、A/B 測試 | 連 GitHub repo |

三家都是**推 GitHub → 自動部署**。設定好之後，你在 `data.js` 改個價格、commit、push，兩分鐘後線上就更新了。這也是為什麼要放 GitHub。

> GitHub Pages 也可以，但 repo 必須是 public（免費方案），而且自訂網域的 HTTPS 偶爾要手動重簽。前三家比較省事。

## 4. 如果你真的要自己管一台伺服器

走 C 方案，或之後生意大到要自架，下面每一項都是「不做會出事」的：

### 4.1 憑證與 HTTPS
- Let's Encrypt + certbot 自動續期，**並且設定續期失敗的告警**。憑證過期的那天你會接到一堆「網站有毒」的客訴。
- 不要自己終結 TLS，交給 Cloudflare 或雲端的 Load Balancer。

### 4.2 備份 —— 最常被跳過、出事最慘的一項
- 資料庫**每日自動備份**，保留 30 天，而且要**放在另一個帳號或另一家雲**（勒索軟體會把同帳號的備份一起加密）。
- **每季實際還原一次**。沒還原過的備份等於沒有備份，這句話請當真。
- 商品圖等上傳檔案放物件儲存（S3 / R2 / GCS），不要放在主機的本機磁碟。

### 4.3 更新與修補
- 作業系統自動安裝安全性更新。
- 應用程式依賴每月更新一次，開 Dependabot 讓 GitHub 自動提 PR。
- **不要在有訂單的時段更新**。台灣電商尖峰通常是晚上 9–11 點跟發薪日。

### 4.4 監控與告警
- **Uptime 監控**：UptimeRobot（免費）每 5 分鐘打一次首頁，掛了發 LINE / Email。
- **錯誤追蹤**：Sentry 免費額度就夠。使用者結帳失敗你要在客訴之前先知道。
- **日誌**：至少保留 30 天，出事時要能查「那筆訂單當下發生什麼」。
- **要盯的數字**：磁碟用量（會滿）、記憶體、錯誤率、結帳成功率。

### 4.5 流量突波 —— 網紅電商的特有風險
你朋友在 IG 限動發一則「開賣了」，五分鐘內湧進來的流量可能是平常的 100 倍。

- 前面一定要有 **CDN**（Cloudflare 即可），靜態資源全部快取。
- 資料庫連線數要設上限，否則會被打爆。
- **開賣前先壓測一次**，用 k6 或 Vegeta 打個幾百 RPS 看看。
- 秒殺型的團購，考慮排隊機制或分批開賣。

### 4.6 機密管理
- 金流的 `HashKey`、`HashIV`、API Token **絕對不能進 git**。用環境變數或平台的 Secrets 功能。
- 已經不小心 commit 進去了：**立刻去金流後台重新產生一組**。從 git 歷史刪掉不夠，它已經外流了。
- repo 開 GitHub Secret Scanning（免費）。

### 4.7 存取控制
- GitHub、主機、金流後台、網域，**全部開兩步驟驗證**。
- 幫忙的人給最小權限，離開時立刻移除。
- 不要共用同一組帳密，出事時查不出是誰。

## 5. 台灣的法規與合規（這部分沒得省）

> 以下是常見要點，不是法律意見。實際開業前請諮詢會計師／律師。

### 5.1 開業
- **商業登記與統一編號**：有實質營業就要辦。個人小規模營業人月營業額 NT$20 萬以下適用查定課徵。
- **營業稅**：一般營業人 5%，每兩個月申報一次。

### 5.2 化粧品（面膜就是化粧品，這條特別重要）
- 適用《**化粧品衛生安全管理法**》。
- **一般化粧品需完成產品登錄**才能販售，並要有 **PIF（產品資訊檔案）**。你是代理／經銷，要跟供應商拿到這些文件的證明。
- **標示**：品名、用途、成分、用法、保存期限、廠商名稱地址電話、產地，缺一不可。
- **廣告不得宣稱療效**。「美白」「除皺」「治療痘痘」「修復受損肌」這類詞可能踩線；違規罰鍰從 NT$4 萬起跳，網紅代言連帶受罰的案例每年都有。
  - 這個樣板已經在頁尾與商品頁放了「本產品為化粧品，非醫療用品，不具療效」，**不要拿掉**。
  - 文案請往「使用感受」寫（「敷完不黏」「隔天上妝比較服貼」），不要往「功效宣稱」寫。
- 建議投保**產品責任險**。

### 5.3 消費者保護
- **7 天猶豫期**（消保法第 19 條）：到貨後 7 天內可無條件解約，這是**鑑賞期不是試用期**。
- 個人衛生用品（面膜、保養品）拆封後可依「通訊交易解除權合理例外情事適用準則」排除，**但你必須在網站上事先明確告知**。本樣板的「購物須知」已經寫了，請保留並依實際政策調整。
- 退換貨規定、運費負擔、客服聯絡方式必須在網站上公告。

### 5.4 個資
- 適用《個人資料保護法》。要有**隱私權政策**：蒐集什麼、為什麼、存多久、怎麼刪。
- 只收必要欄位。不需要身分證字號就不要問。
- **絕對不要自己存信用卡號**。一律用金流商的付款頁或 SDK，讓卡號不經過你的伺服器（否則你就落入 PCI-DSS 的範圍，那是另一個世界的成本）。

### 5.5 發票
- 電子發票是必要的。最省事的做法是**用金流商代開**（綠界、藍新都有整合），不要自己串財政部平台。

## 7. 上線之後的維運節奏

| 頻率 | 要做的事 |
|---|---|
| **每天** | 看訂單、回客服訊息、確認出貨、看網站有沒有掛 |
| **每週** | 看 GA4：流量從哪來、哪個商品被看最多、購物車放棄率 |
| **每月** | 依賴套件更新、還原一次備份試試看、對帳、盤點庫存 |
| **每季** | 檢查憑證與網域到期日、清理沒在賣的商品、檢視價格與運費策略 |
| **每年** | 網域續約（**設行事曆提醒**）、法規有沒有變、保險續保 |

**最容易忘記、忘記最痛的三件事**：網域續約、憑證續期、備份能不能還原。三件都設行事曆提醒。

## 8. 一句話總結

先用開店平台把生意跑起來，把這個 repo 當成品牌的視覺原型與活動落地頁。等到訂單量大到平台的抽成比工程師還貴，再考慮自建 —— 到那時候你也養得起一個工程師了。
