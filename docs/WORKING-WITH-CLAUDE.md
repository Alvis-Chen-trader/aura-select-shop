# 之後怎麼跟 Claude 一起維護這個網站

---

## 為什麼要放 GitHub

因為 GitHub 是我們兩個都看得到、都能改、而且**改了什麼有紀錄**的地方。

- 你可以在手機上開 GitHub App 看程式碼、看我改了什麼。
- 我可以直接讀整個專案的狀態，不用你每次貼一堆程式碼給我。
- 改壞了可以退回上一版（`git revert`），不會回不去。
- 主機（Vercel / Cloudflare Pages）盯著 GitHub，一 push 就自動上線。

如果檔案只在你的電腦裡，上面每一項都沒有。

## 三種協作方式，看你當下在哪

### 1. Claude Code on the web（最推薦）

到 [claude.ai/code](https://claude.ai/code)，選這個 repo，開一個 session 直接講你要什麼。

- 不用裝任何東西，手機也能用。
- 我會在雲端的容器裡把 repo clone 下來、改好、push 到分支、開 PR。
- 你在 GitHub 上按 Merge，網站就更新了。

### 2. Claude Code CLI（在你自己的電腦上）

```bash
npm install -g @anthropic-ai/claude-code
cd 你clone下來的repo
claude
```

適合你想一邊改一邊在瀏覽器看效果的時候。改完自己 commit + push。

### 3. 直接在對話裡問

小問題（「這段 CSS 是什麼意思」「幫我想三個商品文案」）不需要開 session，直接問就好。

## 怎麼給我任務會比較順

### 好的請求長這樣

> 「把 `data.js` 裡的面膜價格從 580 改成 620，原價改成 850，然後在商品頁的規格表加一列『膚質建議：中性偏乾』。」

> 「新增一個商品：茶樹控油化妝水，NT$480，分類清潔，狀態預購中，圖先用現有的 mist.svg。文案我等等給你，先放 placeholder。」

> 「首頁的 hero 在 iPhone SE 上文字會擠成一團，幫我看一下。」

具體、講清楚結果、一次一件事。

### 不太好的請求長這樣

> 「幫我把網站弄好看一點。」

我會問你「哪裡不好看」，然後我們來回三輪才開始動工。與其這樣，不如：截圖圈起來、或指一個你喜歡的網站說「我要這種感覺」。

### 特別有用的一招：給我參考網站

「我要 xxx.com 那種商品卡的排法」比任何形容詞都準確。
（註：我在雲端 session 裡有時候會因為網路政策連不到某些網站 —— 那時候我會直接跟你說，你截圖給我就行。）

## 什麼檔案改什麼

| 你想改的東西 | 去哪個檔案 | 難度 |
|---|---|---|
| 商品、價格、運費、店名、客服資訊 | `assets/js/data.js` | 你自己就能改 |
| 首頁文案、關於我們、常見問題 | `assets/js/data.js` 的 `COPY` | 你自己就能改 |
| 品牌顏色 | `assets/css/style.css` 最上面的 tokens | 你自己就能改 |
| 商品圖 | 丟進 `assets/img/`，改 `data.js` 的檔名 | 你自己就能改 |
| 版面結構、加新區塊、新頁面 | `views.js` / `app.js` | 找我 |
| 加購物車新功能、串金流 | 很多檔案 | 找我，而且要先討論 |

**上面四個「你自己就能改」是有意設計的。** 日常改文案改價格不該每次都要找人，那太慢了。

## 建議的工作流程

```
你在 IG 收到問題／想改東西
        ↓
開 Claude Code session，講清楚要改什麼
        ↓
我改完 → push 到分支 → 開 PR
        ↓
你在 GitHub 上看 PR（或直接看 Vercel 自動產生的預覽網址）
        ↓
OK → Merge → 兩分鐘後正式站更新
不 OK → 在 PR 留言告訴我哪裡不對 → 我再改
```

**請不要直接改 `main` 分支。** 走 PR 的好處是：改壞了正式站還是好的，而且你有機會在上線前先看一眼。

## 我能做什麼、不能做什麼

**我可以**

- 改版面、加頁面、改文案、修 bug、加功能
- 讀你貼的錯誤訊息，找出問題在哪
- 幫你評估「要不要自建 vs 用平台」這種決策，並說明取捨
- 寫商品文案初稿（但**你要自己確認法規用詞**，見下）
- 設定部署、GitHub Actions、監控

**我不行 / 你不該讓我做**

- **拿到你的金流金鑰、後台密碼**。這些永遠不要貼給我，也不要進 repo。要設定的話，我告訴你去哪貼，你自己貼。
- **代替法遵確認**。化粧品廣告用詞、退換貨政策、個資條款，我可以給你草稿跟提醒，但送出前請找懂法規的人看過。踩到化粧品廣告的線是實際會被罰錢的。
- **保證我寫的程式沒有 bug**。所以才要有 PR、有預覽網址、有備份。
- **代你按下「上線」**。牽涉到真的收錢、真的寄信給客人的動作，我會先問你。

## 一開始就先做的兩件事

1. **在 repo 根目錄放一個 `CLAUDE.md`**（這個 repo 已經有了）。裡面寫專案的慣例、你的偏好、不要碰的地方。每次我開始工作都會先讀它，你不用每次重講一遍。
   - 例如：「文案一律用繁體中文，不要用簡體詞彙」「價格一律含稅」「不要自作主張改品牌色」。
2. **接上自動部署**（Vercel 或 Cloudflare Pages），並開啟 PR 預覽。這樣每個 PR 都會有一個獨立網址，你點進去就看得到改完長怎樣，不用自己跑起來。
